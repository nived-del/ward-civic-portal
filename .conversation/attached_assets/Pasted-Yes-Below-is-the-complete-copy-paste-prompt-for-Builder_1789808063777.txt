# MINIMAL WARD-LEVEL CIVIC ISSUE TRACKING PORTAL

# 6. OTP REGISTRATION FLOW

After the registration form is submitted:

```text
Registration Form
        ↓
Validate Information
        ↓
Generate 6 Digit OTP
        ↓
Send OTP
        ↓
OTP Verification Page
        ↓
Verify OTP
        ↓
Create Verified Account
        ↓
Registration Successful
        ↓
Login Page
```

The user should NOT be considered fully registered/verified until the OTP is successfully verified.

---

# 7. OTP REQUIREMENTS

OTP must:

* Contain exactly 6 digits
* Be randomly generated
* Expire after 5 minutes
* Be usable only once
* Allow maximum 5 incorrect attempts
* Have a resend cooldown
* Invalidate the previous OTP when a new OTP is generated

Use secure random OTP generation.

For the initial project, store OTP information temporarily in memory.

Later it can be moved to an SQL table.

4. Attach user information to request
5. Reject unauthorized requests

# 14. PASSWORD SECURITY

Use bcrypt.

Never store passwords as plain text.

Registration:

```text
Password
   ↓
bcrypt hash
   ↓
Store hash
```

Login:

```text
Entered Password
       ↓
bcrypt.compare()
       ↓
Valid / Invalid
```

Never return:

* Password
* Password hash
* OTP
* OTP hash

in normal API responses.
